## Инструменты и их особенности

- `Filesystem:list_allowed_directories` — вызывать первым в сессии; заодно «пробуждает» остальные Filesystem-инструменты.
- `Filesystem:write_file` — основной способ сохранять заметки, перезаписывает файл целиком.
- `Filesystem:copy_file_user_to_claude` — копирует PDF в песочницу для OCR; иногда `Tool not found` или зависание — просто повторить вызов.
- `Filesystem:search_files` (`path` + `pattern`, с `*`) — искать точные имена файлов перед копированием: бывают лишние пробелы, другой порядок слов.
- `Filesystem:read_file` — только текстовые файлы, не PDF; годится читать уже созданные .md перед правкой.
- Инструмента удаления файлов нет — ненужное перемещать в `_архив_черновиков` через `move_file`, либо перезаписывать безобидным текстом.
- `Google Drive:create_file` ненадёжен («No approval received») — всегда писать напрямую через Filesystem. `Google Drive:read_file_content`/`search_files` — резервный источник чтения.

## Обработка сканов (OCR)

1. `pdfinfo file.pdf | grep Pages`, затем `pdftotext -layout file.pdf -` — если пусто (только `\f`), это скан.
2. `pdftoppm -jpeg -r 200 file.pdf /tmp/prefix` (200dpi лучше 150 для мелкого текста).
3. `tesseract image.jpg stdout -l rus --psm 6`. Если пакет `rus` отсутствует: `apt-get install -y tesseract-ocr-rus`.
4. Если пусто — пробовать `--psm 3`/`--psm 4`, поворот (`convert -rotate`). После 2–3 неудачных попыток (обычно рукописный курсив) — не тратить время дальше: помечать `> [!caution] Конвертация не удалась`, тег `требует_проверки`, двигаться дальше. Печатные автоотчёты обычно читаются лучше рукописных направлений.
5. Дозировки лекарств из OCR — всегда помечать как требующие сверки с оригиналом.
6. В плотных числовых таблицах (биохимия на 20+ строк) проверять правдоподобность каждого значения относительно референса; физиологически невозможные цифры (например «Hb 490 г/л») — помечать `⚠️ сомнительно`, не угадывать точное число.

## Дублирующиеся файлы

Иногда один и тот же результат сохранён в архиве дважды под разными именами/датами (повторная распечатка, тот же № ИБ и заказ). Перед созданием новой заметки — если значения и № ИБ совпадают с уже существующей заметкой, дубликат не создавать, находку зафиксировать в индексе.

## Схема заметки (обязательна для всех новых файлов, без исключений)

### Принцип атомарности

Один анализ/событие = одна заметка. Многопанельные PDF визита — разбивать на отдельные заметки по категориям, связывая через `related`.

⚠️ «Один день» ≠ «одно событие»: два обращения/визита в разные дни или время суток, каждое со своим номером справки — это два разных события и две разные заметки, даже если обрабатываются в одной партии. Признак «одна заметка» — один заказ/один номер документа/один забор материала, а не тематическая близость.

### YAML frontmatter — только эти имена полей, латиница/English snake_case

```yaml
---
type: анализ            # анализ | заключение | консультация | выписка | инструментальное | административный
category: копрограмма    # см. таксономию ниже
patient: Д. К.
date_birth: 2021-02-18
date: YYYY-MM-DD
institution: ...
doctor: ...
document_number: ""
tags: [медицина, ...]
values: {...}            # только для количественных показателей
abnormal: [...]
related: ["[[...]]"]
source_pdf: ""
---
```

Для `выписка`/`заключение` дополнительно — поле `diagnosis` (строка с полным диагнозом).

⚠️ Не использовать русские имена полей (`пациент`, `дата_анализа` и т.п.).

### Именование файлов

`YYYY-MM-DD_Категория_Учреждение.md`. При нескольких документах одной категории в один день — суффикс `_1`, `_2`.

### Таксономия категорий (актуальный список)

`копрограмма`, `кальпротектин`, `скрытая_кровь`, `дисбактериоз`, `микробиология`, `микробиология_нос`, `биохимия_комплексная`, `оак`, `иммунограмма`, `trec_krec`, `целиакия_скрининг`, `h_pylori`, `токсины_cl_difficile`, `эластометрия_печени`, `узи_брюшной_полости`, `узи_кишечника`, `эхокардиография`, `эгдс`, `патогистология`, `кт_головного_мозга`, `экг`, `консультация_лор`, `консультация_пульмонолог`, `консультация_гастроэнтеролог`, `консультация_иммунолог`, `консультация_невролог`, `консилиум`, `приёмный_покой`, `выписка_госпитализация`, `мрэк`, `программа_реабилитации`, `семейный_скрининг` (анализы членов семьи — одна сводная заметка со ссылкой из заметки Д. К.), `выписка_прививки`.

### Тело заметки

Таблицы результатов → callout `[!warning]`/`[!success]`/`[!caution]`/`[!important]` для отклонений → таблица динамики (если есть предыдущие точки той же категории) → навигация `← [[...]] · → [[...]]` в конце.

### Двусторонние связи — обязательно

При вставке новой точки в хронологическую цепочку — обновлять `related` и текст обеих соседних заметок (более ранней и более поздней), не только новой. Актуализировать таблицы динамики в соседних заметках («было/стало»).

## Чувствительные темы в архиве — обычная медицинская точность, без замалчивания и без сенсационности

Законный медицинский архив для нужд ухода за ребёнком, который ведёт отец. Регулярно встречаются и должны отражаться фактически:

- Задержка психоречевого развития / расстройство аутистического спектра (РАС) — упоминается неврологами и в кодах МКБ с 2023 года.
- Инвалидность ребёнка (МРЭК, СУЗ 4).
- Семейный анамнез: онкологическое заболевание кишечника по отцовской линии (консультация иммунолога 10.10.2023).
- Эпизод с подозрением на сахарный диабет (итог — транзиторная гипергликемия, не диабет).

При каждой партии: обновлять `Индекс_анализов.md`, чинить двусторонние ссылки на стыке новых и старых заметок, следить за единой схемой полей, проверять даты внутри документов.
