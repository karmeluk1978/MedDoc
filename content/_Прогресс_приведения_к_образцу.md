# Приведение заметок архива к образцу — цели, прогресс, промт

## Цель

Привести **все заметки** папки `Медицинские документы` (около 484 файлов) к единому формату образцовой заметки с учётом содержимого каждой. Служебные файлы (папка `Динамика по показателям`, шаблоны, индексы) не трогаем, пока пользователь не скажет иначе.

Образцы:
- `2026-05-25_Биохимия-HELIX` — основной образец структуры и таблиц
- `2026-07-10_КТ-ОГК-ОНП-шея_ДИКБ` — образец блока «Заключение» для инструментальных исследований и консультаций

## Формат (сводка правил)

1. **Структура:** frontmatter → `# Заголовок` → строки реквизитов **одним блоком без пустых строк** (`**Учреждение:**`, `**Пациент:**`, `**Дата рождения:**`, `**Протокол/Дата заказа/Дата проведения/Обследование/Врач:**` и т.д.) → `> [!info] Плановое исследование` → таблицы/текст исследования → `## Заключение` в конце → футер `← [[предыдущая]] · → [[следующая]]`.
2. **`[!info] Плановое исследование` — всегда**, после **всех** строк реквизитов. Содержание берём из документов: в одном заказе с чем сдано (кальпротектин, скрытая кровь, дисбактериоз), ссылка на предыдущий анализ этой категории; «плановое» пишем только если назначение есть в документах (например, в консультации врача), иначе нейтральная формулировка.
3. **Раздел «Пациент»** (таблица ФИО/пол/дата рождения/возраст) — убираем (данные есть в шапке).
4. **Раздел «Динамика ключевых показателей»/«Динамика»** — убираем, вместо него в таблицах колонки **«Оценка»** (вместо «Статус»; значки ✅/⚠️/⛔ только здесь, не в «Референсе») и **«Δ vs <дата предыдущего анализа>»**.
5. **Δ:** `⬆️/⬇️ (было X)`, `=`, `⚠️ Ухудшение (было X)`, `✅ Улучшение (было X)`, `—` если раньше не измерялось или шкалы лабораторий несопоставимы. Считаем к **хронологически предыдущему** анализу той же категории (любого учреждения; если учреждение другое — указываем в заголовке колонки, например `Δ vs 24.12.2024 (ДИКБ)`).
6. **Заключение:** старый раздел «Заключение»/«Заключение врача» убираем, информацию переносим в новый `## Заключение` с двумя callout'ами: `> [!success] Без острой патологии` (что в норме) и `> [!warning] Особенности, требующие учёта` (маркированный список отклонений; ссылки `[[...]]` только если связь прямо следует из документов).
7. **Цепочки «←/→»** в конвертируемых заметках приводим к хронологическому порядку (между разными учреждениями тоже). Если соседняя заметка ещё не конвертирована, её «←/→» поправить при её конвертации.
8. Значения брать **только из самих заметок/сканов**, ничего не выдумывать. Если данных для Δ нет, ставить «—».

## Рабочие приёмы и уроки

- **Инструменты:** основной — Obsidian MCP (`get_vault_file(s)`, `create_vault_file` с `expectedContent` — текущий текст файла без строки `URI:`, при совпадении перезаписывает файл целиком). Запасной — Filesystem MCP: `read_text_file`, `edit_file` с точным `oldText` (путь вида `C:\Хранилище\Хранилище\Медицинские документы\<имя>.md`), `search_files` с glob-паттерном, например `2024-*Копрограмма*`. Иногда Obsidian-инструменты «пропадают» на ход — тогда вызвать `tool_search`, либо переключиться на Filesystem.
- **Точность `oldText`:** при `edit_file` правка применяется целиком или никак; ошибки возникали из-за расхождений в одном слове («был»/«было», «Отрицательный»/«Отрицательные»). Копировать текст из последнего чтения дословно.
- **Проверять после правки:** в `edit_file`-выводе diff; опечатки (были «неперевареные», «кальпротекин») — читать результат.
- **Разные форматы старых заметок:** в части заметок уже есть свои Δ-колонки, «Динамика» с другим набором показателей, `---` перед футером, отдельная pH-таблица (превращаем в строку таблицы микроскопии), «Заключение» обычным текстом.
- **Заметки из выписок** (только 2–3 показателя) — таблица остаётся короткой, Δ только по тем показателям, что есть.
- **Две лаборатории (3ДКБ и ДИКБ):** шкалы разные («+/++/+++» против «отсутствует/единичные» и числовых значений); для лейкоцитов и т.п. Δ часто несопоставима — ставить «—».
- **Память:** в файлы памяти нельзя записывать возраст ребёнка; прогресс здесь, в служебной заметке.

## Промт для новой сессии

> Мы приводим заметки медицинского архива в Obsidian к единому образцу. Прочитай:
> 1. файл правил в памяти проекта («Правила оформления заметок…»);
> 2. эту служебную заметку `_Прогресс_приведения_к_образцу` в папке `Медицинские документы` (цели, формат, прогресс, уроки);
> 3. образцовые заметки `2026-05-25_Биохимия-HELIX` и `2026-07-10_КТ-ОГК-ОНП-шея_ДИКБ`.
>
> Затем продолжи с первого пункта раздела «Осталось». Для каждой заметки: прочитай её и предыдущий по времени анализ той же категории, приведи к формату (реквизиты одним блоком → `[!info] Плановое исследование` → таблицы с колонками «Оценка» и «Δ vs <дата>» → `## Заключение` с `[!success]` и `[!warning]` → футер `← · →` в хронологическом порядке), значения бери только из самих заметок. Записывай через Obsidian MCP (`create_vault_file` с `expectedContent`), при проблемах — Filesystem MCP. После категории проверь дубли заголовков и битые ссылки. По ходу обновляй раздел «Прогресс» в этой заметке. Ничего не выдумывай: если данных для Δ нет, ставь «—». Перед массовыми изменениями формата задавай уточняющие вопросы.
