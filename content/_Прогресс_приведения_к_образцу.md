# Приведение заметок архива к образцу — цели, прогресс, промт

## Цель

Привести **все заметки** папки `Медицинские документы` (около 500 файлов) к единому формату образцовой заметки с учётом содержимого каждой. Служебные файлы (папка `Динамика по показателям`, `_шаблоны_по_категориям`, `Приём препаратов`, индексы) не трогаем, пока пользователь не скажет иначе.

Образцы:
- `2026-05-25_Биохимия-HELIX` — основной образец структуры и таблиц
- `2026-07-10_КТ-ОГК-ОНП-шея_ДИКБ` — образец блока «Заключение» для инструментальных исследований и консультаций

## Формат (сводка правил)

1. **Структура:** frontmatter → `# Заголовок` → строки реквизитов **одним блоком без пустых строк** (`**Учреждение:**`, `**Пациент:**`, `**Дата рождения:**`, `**Протокол/Дата заказа/Дата проведения/Обследование/Врач:**` и т.д.) → `> [!info] Плановое исследование` → таблицы/текст исследования → `## Заключение` в конце → футер `← [[предыдущая]] · → [[следующая]]`.
2. **`[!info] Плановое исследование` — всегда**, после **всех** строк реквизитов. Содержание берём из документов: в одном заказе с чем сдано (кальпротектин, скрытая кровь, дисбактериоз), ссылка на предыдущий анализ этой категории; «плановое» пишем только если назначение есть в документах (например, в консультации врача), иначе нейтральная формулировка. Прежние callout'ы `[!info]`/`[!note]` с примечаниями (например, «Дата в имени файла исправлена», «Бланк содержит сокращённый набор показателей») сохраняем как `[!note]`/цитату после основного `[!info]`.
3. **Раздел «Пациент»** (таблица ФИО/пол/дата рождения/возраст) — убираем (данные есть в шапке).
4. **Раздел «Динамика ключевых показателей»/«Динамика»** — убираем, вместо него в таблицах колонки **«Оценка»** (вместо «Статус»; значки ✅/⚠️/⛔ только здесь, не в «Референсе») и **«Δ vs <дата предыдущего анализа>»**.
5. **Δ:** `⬆️/⬇️ (было X)`, `=`, `⚠️ Ухудшение (было X)`, `✅ Улучшение (было X)`, `—` если раньше не измерялось или шкалы лабораторий несопоставимы. Считаем к **хронологически предыдущему** анализу той же категории (любого учреждения; если учреждение другое — указываем в заголовке колонки, например `Δ vs 24.12.2024 (ДИКБ)`). **Если в один день сданы анализы в двух лабораториях** — Δ считаем к предыдущему анализу **той же лаборатории** (шкалы сопоставимы), а цепочку «←/→» оставляем хронологической.
6. **Заключение:** старый раздел «Заключение»/«Заключение врача» убираем, информацию переносим в новый `## Заключение` с двумя callout'ами: `> [!success] Без острой патологии` (что в норме) и `> [!warning] Особенности, требующие учёта` (маркированный список отклонений; ссылки `[[...]]` только если связь прямо следует из документов).
7. **Цепочки «←/→»** в конвертируемых заметках приводим к хронологическому порядку (между разными учреждениями тоже). Если соседняя заметка ещё не конвертирована, её «←/→» поправить при её конвертации.
8. Значения брать **только из самих заметок/сканов**, ничего не выдумывать. Если данных для Δ нет, ставить «—».

## Рабочие приёмы и уроки

- **Структура папок изменилась:** заметки теперь лежат в подпапках по годам: `Медицинские документы/2023/2023-06-20_Копрограмма_3ДКБ.md`. В Obsidian MCP использовать пути с папкой года. Старые пути без года могут не находиться (`File not found`) — это не отсутствие заметки; получить актуальный список: `list_vault_files` с `directory: Хранилище/Медицинские документы`.
- **Инструменты:** основной — Obsidian MCP: `get_vault_file(s)`, `create_vault_file` с `expectedContent` (текущий текст файла без строки `URI:`; при совпадении перезаписывает файл целиком). Запасной — Filesystem MCP (`read_text_file`, `edit_file` с точным `oldText`, `search_files`), но его пути могли устареть из-за переноса в папки годов. Иногда нужные инструменты «пропадают» на ход — вызвать `tool_search` с описанием нужного инструмента.
- **Точность `edit_file`/`expectedContent`:** правка применяется целиком или никак; ошибки возникали из-за расхождений в одном слове («был»/«было», «Отрицательный»/«Отрицательные»). Копировать текст из последнего чтения дословно. После правки читать результат — были опечатки («неперевареные», «кальпротекин»).
- **Разные форматы старых заметок:** где-то уже есть свои Δ-колонки, «Динамика» с другим набором показателей, `---` перед футером, отдельная pH-таблица (превращаем в строку таблицы микроскопии), «Заключение» обычным текстом.
- **Заметки из выписок** (только 2–3 показателя) — таблица остаётся короткой, Δ только по тем показателям, что есть.
- **Две лаборатории (3ДКБ и ДИКБ), а также Синэво:** шкалы разные («+/++/+++» против «отсутствует/единичные» и числовых значений); для лейкоцитов и т.п. Δ часто несопоставима — ставить «—».
- **Память:** в файлы памяти нельзя записывать возраст ребёнка; прогресс ведём здесь, в служебной заметке.

## Промт для новой сессии

> Мы приводим заметки медицинского архива в Obsidian к единому образцу. Прочитай:
> 1. файл правил в памяти проекта («Правила оформления заметок…»);
> 2. эту служебную заметку `_Прогресс_приведения_к_образцу` в папке `Медицинские документы` (цели, формат, прогресс, уроки);
> 3. образцовые заметки `2026-05-25_Биохимия-HELIX` и `2026-07-10_КТ-ОГК-ОНП-шея_ДИКБ`.
>
> Заметки лежат в подпапках по годам (`Медицинские документы/<год>/…`). Продолжи с первого пункта раздела «Осталось». Для каждой заметки: прочитай её и предыдущий по времени анализ той же категории, приведи к формату (реквизиты одним блоком → `[!info] Плановое исследование` → таблицы с колонками «Оценка» и «Δ vs <дата>» → `## Заключение` с `[!success]` и `[!warning]` → футер `← · →` в хронологическом порядке), значения бери только из самих заметок. Записывай через Obsidian MCP (`create_vault_file` с `expectedContent`). После категории проверь дубли заголовков и битые ссылки. По ходу обновляй раздел «Прогресс» в этой заметке. Ничего не выдумывай: если данных для Δ нет, ставь «—». Перед массовыми изменениями формата задавай уточняющие вопросы.
